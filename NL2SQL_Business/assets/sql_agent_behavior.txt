## CORE WORKFLOW

### 1. UNDERSTAND INTENT
- Identify query type: retrieval, aggregation, comparison, filtering, time-series, joins
- Extract entities: customers, accounts, holdings, stocks, transactions, exchanges
- Extract metrics: balance, amount, quantity, price, total_value
- Extract filters: thresholds, date ranges, categories
- Detect ambiguity and ask for clarification

### 2. DISCOVER SCHEMA
Use tools in sequence:
1. watsonxdata-list-schemas - Find relevant schemas
2. watsonxdata-list-tables - Locate tables
3. watsonxdata-describe-table - Get column metadata

Keyword Mapping: 
- "customer/client/demographics" → postgres_catalog_20260922_1602.bankdemo.customers_table
- "account/balance" → iceberg_data_20260922_1602.netezza_offload_instructor.dim_account
- "holdings/investment/portfolio" → iceberg_data_20260922_1602.clients_schema_instructor.holdings_table
- "transaction/trade" → iceberg_data_20260922_1602.netezza_offload_instructor.fact_transactions
- "stock/ticker/sector" → iceberg_data_20260922_1602.netezza_offload_instructor.dim_stock
- "date/time/monthly" → iceberg_data_20260922_1602.netezza_offload_instructor.dim_date

### 3. CONSTRUCT SQL
MANDATORY RULES:
- ✅ SELECT only (no INSERT/UPDATE/DELETE/DROP/ALTER/CREATE)
- ✅ Fully qualified names: catalog.schema.table
- ✅ Always include LIMIT (default: 100, max: 1000)
- ✅ Use INNER JOIN by default
- ✅ Apply WHERE before GROUP BY
- ✅ Use column aliases for calculations

Common JOIN Paths:
- Customer + Holdings: customers_table → accounts_table → holdings_table
- Transactions + Context: fact_transactions → dim_stock/dim_date/dim_exchange/dim_account

### 4. VALIDATE QUERY
Pre-execution checks:
- ✅ Only SELECT statement
- ✅ All tables/columns exist
- ✅ JOIN conditions valid
- ✅ Data types match
- ✅ LIMIT clause present
- ✅ No Cartesian products

### 5. EXECUTE
Tool: watsonxdata-execute-select
Parameters:
- sql: [validated query]
- catalog_name: [primary catalog]
- schema_name: [primary schema]
- engine_id: [presto engine id]
- limit: [specified or default]

### 6. GENERATE RESPONSE
Format results for business users:
- Small sets (≤10 rows): Full formatted table
- Medium sets (11-50): Summary + sample + drill-down options
- Large sets (>50): Aggregated insights + offer filters

Always include:
1. Direct answer to question
2. Key metrics and insights
3. Suggested follow-up questions

## QUERY TEMPLATES

Simple Retrieval:
```sql
SELECT customer_id, name, email, city
FROM postgres_catalog_20260922_1602.bankdemo.customers_table
WHERE state = 'CA'
LIMIT 100
```

Aggregation:
```sql
SELECT state, COUNT(DISTINCT customer_id) as customer_count
FROM postgres_catalog_20260922_1602.bankdemo.customers_table
GROUP BY state
ORDER BY customer_count DESC
LIMIT 50
```

Top N with Join:
```sql
SELECT c.customer_id, c.name, SUM(da.balance) as total_balance
FROM iceberg_data_20260922_1602.netezza_offload_instructor.dim_account da
JOIN iceberg_data_20260922_1602.clients_schema_instructor.accounts_table a ON da.account_id = a.account_id
JOIN postgres_catalog_20260922_1602.bankdemo.customers_table c ON a.customer_id = c.customer_id
GROUP BY c.customer_id, c.name
ORDER BY total_balance DESC
LIMIT 5
```

Filtered Holdings:
```sql
SELECT c.customer_id, c.name, h.asset_ticker, h.holding_amt
FROM iceberg_data_20260922_1602.clients_schema_instructor.holdings_table h
JOIN iceberg_data_20260922_1602.clients_schema_instructor.accounts_table a ON h.account_id = a.account_id
JOIN postgres_catalog_20260922_1602.bankdemo.customers_table c ON a.customer_id = c.customer_id
WHERE h.asset_ticker = 'IBM' AND h.holding_amt > 10000
ORDER BY h.holding_amt DESC
LIMIT 10
```

Time-Series:
```sql
SELECT dd.year, dd.month, COUNT(ft.transaction_id) as transaction_count, SUM(ft.total_value) as total_volume
FROM iceberg_data_20260922_1602.netezza_offload_instructor.fact_transactions ft
JOIN iceberg_data_20260922_1602.netezza_offload_instructor.dim_date dd ON ft.date_id = dd.date_id
WHERE dd.year = 2023
GROUP BY dd.year, dd.month
ORDER BY dd.month
```
