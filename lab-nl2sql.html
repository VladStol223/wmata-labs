Natural Language to SQL Agent

Build an AI-powered agent in watsonx Orchestrate that converts plain-English questions into SQL queries, executes them against watsonx.data, and returns formatted results — no SQL expertise required.

⏱ 45–60 minutes 🤖 watsonx Orchestrate 💻 No coding required 🔗 UI-based

1. Introduction

In this lab, you'll create a Natural Language to SQL (NL2SQL) agent that understands natural language questions and automatically converts them into SQL queries to retrieve data from watsonx.data. Unlike traditional methods that require SQL knowledge, this agent allows business users to ask questions in plain English and get accurate answers from your data lakehouse.

What This Lab Demonstrates

  • No coding required — build the agent entirely through the watsonx Orchestrate UI
  • Direct data access — connects directly to watsonx.data without intermediate deployments
  • Business-friendly — designed for analysts, managers, and non-technical users
  • Intelligent query generation — automatically converts questions to SQL
  • Multi-table joins — handles complex queries across multiple data sources

What You'll Build

An intelligent agent that:

  1. Accepts natural language questions from users
  2. Analyzes the question to understand intent
  3. Generates appropriate SQL queries
  4. Executes queries against watsonx.data
  5. Generates insights and suggests relevant follow-up questions
  6. Formats and presents results in a user-friendly way

Architecture

User Question (Natural Language)
        ↓
watsonx Orchestrate Agent
        ↓
LLM analyzes question → Generates SQL
        ↓
SQL Query Tool → watsonx.data (Presto)
        ↓
Query Results → Formatted Response
        ↓
User receives answer

4. Create NL2SQL Agent in watsonx Orchestrate

4.1 Access watsonx Orchestrate

  1. Go to IBM Cloud Resources
  2. Under AI / Machine Learning, find your watsonx Orchestrate instance
  3. Click Launch watsonx Orchestrate

4.2 Configure watsonx.data Connection

Before the agent can query data, it needs a connection to watsonx.data. Complete all three prerequisite sections below, then configure the connection in watsonx Orchestrate.

You will need your env.txt credentials file (from student_creds/) open throughout this section. It contains WXD_USER, WXD_API_KEY, WXDATA_CRN, and WXDATA_MCP_ENDPOINT.

Prerequisite 1 — Generate an ApiKey Authorization Token

The API key cannot be used directly — you must Base64-encode it first.

  1. Open your env.txt file and locate WXD_USER and WXD_API_KEY.
  2. Run the appropriate command for your OS to generate the token:

    Mac / Linux:

    echo -n "<WXD_USER>:<WXD_API_KEY>" | base64

    Windows PowerShell:

    [Convert]::ToBase64String([Text.Encoding]::ASCII.GetBytes("<WXD_USER>:<WXD_API_KEY>"))
    Replace <WXD_USER> and <WXD_API_KEY> with your actual values.
  3. Copy the output token and save it in env.txt as WXDATA_TOKEN.

Prerequisite 2 — Locate Your watsonx.data Instance CRN

Find WXDATA_CRN in your env.txt file. It looks like:

WXDATA_CRN="crn:v1:bluemix:public:lakehouse:us-south:a/1234567890abcdef:..."

Prerequisite 3 — Identify Your MCP Server Endpoint

Find WXDATA_MCP_ENDPOINT in your env.txt file, or construct it from the table below:

Configure the Connection in watsonx Orchestrate

  1. In watsonx Orchestrate, click the hamburger menu (☰) → Manage → Connections, then click Add Connection.
  2. Enter a Connection ID: watsonx_data_YOUR_NAME (e.g. watsonx_data_john_smith), then click Save and continue.
    Click Continue.
  3. Draft environment — select Key Value Pair authentication, then add two credentials:
    KeyValue
    authorizationBasic <WXDATA_TOKEN> — include "Basic " (with a space) before the token
    authinstanceidYour WXDATA_CRN value
    Click Next.
  4. Live environment — repeat the same two credentials, then click Finish. Wait for "Connection Creation successful".
Connection is configured. Return here and continue with step 4.3.

4.3 Create New Agent

  1. From the hamburger menu (☰), select Build
  2. Click Create Agent
  3. Select Create from Scratch
  4. Configure basic information:
    • Name: NL2SQL Agent - [Your Name]
    • Description: Natural language interface to query watsonx.data. Ask questions about customers, accounts, holdings, and transactions in plain English - no SQL required.
    Click Create
  5. You should now see the agent configuration page. Click Deploy in the top navigation bar, then select the Orchestrate Chat dropdown. Click Edit and create a Welcome Message:
    Welcome to Data Insights! Ask me about customers, accounts, holdings, or transactions
  6. Add 3 Quick Start Prompts: 
    How many customers do we have?
Show me 5 IBM holdings
What's the total balance across all accounts?

4.4 Add watsonx.data MCP Server Tools

These tools let the agent execute SQL queries against watsonx.data.

  1. First, confirm the MCP server is available. In the Toolset section, under Tools, click Add tool.
    Select MCP server.
    Select Manage MCP Servers and confirm watsonx-data-mcp-server is listed. Close the window.
  2. Now add the tools. Click Add tool again, then in Local Instance, search for and add each of the following:
    watsonxdata-list-engines

    List available Presto and Spark compute engines

    watsonxdata-list-schemas

    List database schemas in a catalog

    watsonxdata-list-tables

    List tables in a schema

    watsonxdata-describe-table

    Get detailed schema and metadata for a table

    watsonxdata-execute-select

    Execute read-only SELECT queries against watsonx.data

    Select each tool and click Add to agent.

4.5 Configure Agent Behavior

  1. Verify that sql_agent_behavior.txt exists in the assets/ folder with correct catalog values from your env.txt file. If not, follow the Create Behavior file guide in automation/behavior/README.md.
  2. Paste the contents of sql_agent_behavior.txt into Behavior → Instructions

4.6 Add Guidelines

While behavior instructions provide the "how," guidelines provide the "must/must not" boundaries. Add each rule below by clicking Add Guideline, filling in the three fields, and clicking Save.

Rule nameConditionAction
enforce_select_only_queries When constructing or executing any SQL query MUST only generate and execute SELECT statements. Immediately reject any INSERT, UPDATE, DELETE, DROP, ALTER, CREATE, TRUNCATE, MERGE, GRANT, or REVOKE statements. Explain to user that only read-only queries are permitted.
clarify_ambiguous_requests When user question has multiple possible interpretations or missing key details MUST ask clarifying questions with 2–4 specific options before proceeding. Do not guess at user intent. Provide numbered interpretation choices and ask user to select which matches their need.
enforce_tool_sequence When discovering schema and constructing queries MUST follow this tool sequence: watsonxdata-list-schemas → watsonxdata-list-tables → watsonxdata-describe-table → watsonxdata-execute-select. Do not skip steps. Always verify table structure before constructing queries.
apply_default_limit When constructing non-aggregation queries MUST include LIMIT clause with default value of 100 rows (maximum 1000 rows).
provide_business_insights When presenting any query results MUST provide insights and interpretation for all metrics. Do not present raw data without explanation. Include key findings, patterns, and suggest 2–4 relevant follow-up questions. Format currency with $ and thousand separators.

After adding all five rules, click Save.

5. Test the NL2SQL Agent

5.1 Preview Mode Testing

Before deploying, test the agent in preview mode.

  1. The preview panel should be visible on the right side of the screen.
  2. Start with: Hello, what can you do? — the agent should explain its capabilities.
Test 1 – Customer Lookup

Who are the 5 oldest customers?

Expected SQL generated:

SELECT customer_id, name, age
FROM postgres_catalog_20260922_1602.bankdemo.customers_table
ORDER BY age DESC
LIMIT 5

Returns: list of oldest customers, key insights, suggested follow-up questions.

Test 2 – Investment Analysis

Who are the top 5 customers with the highest total investment value in holdings?

Expected SQL generated:

SELECT c.customer_id, c.name, SUM(h.holding_amt) AS total_investment
FROM iceberg_data_20260513_1540.clients_schema_instructor.holdings_table h
INNER JOIN iceberg_data_20260513_1540.clients_schema_instructor.accounts_table a
  ON h.account_id = a.account_id
INNER JOIN postgres_catalog_20260922_1602.bankdemo.customers_table c
  ON a.customer_id = c.customer_id
GROUP BY c.customer_id, c.name
ORDER BY total_investment DESC
LIMIT 5

Returns: top 5 customers, key insights, follow-up questions.

Test 3 – Cross-Table Join

List all customers who have invested in IBM and show their holdings

Expected SQL generated:

SELECT c.customer_id, c.name, h.asset_ticker, h.holding_amt
FROM iceberg_data_20260513_1540.clients_schema_instructor.holdings_table h
INNER JOIN iceberg_data_20260513_1540.clients_schema_instructor.accounts_table a
  ON h.account_id = a.account_id
INNER JOIN postgres_catalog_20260922_1602.bankdemo.customers_table c
  ON a.customer_id = c.customer_id
WHERE h.asset_ticker = 'IBM'
ORDER BY h.holding_amt DESC
LIMIT 100

Returns: list of IBM investors, holdings, insights.

View Reasoning: Click Show reasoning in any response, then expand Step 1 to see which tool was used and how the agent interpreted your question to generate SQL.

8. Troubleshooting

Issue: "Connection failed" Error

Symptoms: Agent cannot connect to watsonx.data; tool calling fails immediately.

Solutions:

  • Verify connection credentials in env.txt
  • Check that the watsonx.data instance is running
  • Confirm network connectivity
  • Re-test the connection in Orchestrate
  • Verify MCP server is configured correctly

Issue: "No data returned" for Valid Queries

Symptoms: Query executes but returns empty results when data should exist.

Solutions:

  • Verify table names are correct (catalog.schema.table)
  • Check that data was loaded in the earlier lab setup
  • Test the query directly in the watsonx.data UI
  • Check for case sensitivity in string comparisons

Issue: Agent Generates Incorrect SQL

Symptoms: SQL syntax errors, wrong tables/columns, query doesn't match question intent.

Solutions:

  • Review agent instructions for clarity
  • Add more example queries to instructions
  • Provide clearer data schema information
  • Rephrase your question more specifically

Issue: Agent Doesn't Understand Question

Symptoms: Agent asks for clarification repeatedly or generates irrelevant queries.

Solutions:

  • Rephrase the question more clearly
  • Be more specific about what you want
  • Use terminology from the data schema
  • Break complex questions into simpler parts
